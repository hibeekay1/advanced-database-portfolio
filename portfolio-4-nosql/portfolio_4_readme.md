## 1. Executive Summary
As Ibukun Investment Management Company expands its digital asset management capabilities, relational schemas alone cannot efficiently capture dynamic, rapidly evolving financial data payloads. Portfolio 4 integrates **NoSQL semi-structured JSON document storage** directly into the Oracle database environment. This hybrid approach enables IIMC to store real-time financial market feeds, client-specific risk profiles, and complex asset allocation preferences without rigid schema restrictions.

---

## 2. Technical Implementation Architecture
The core of Portfolio 4 centers around the `client_portfolio_payloads` table, utilizing Oracle’s native `JSON` datatype:

* **Flexible Schema Design:** Decouples dynamic telemetry and client preference payloads from rigid table definitions.
* **ACID + Document Interoperability:** Allows relational metadata (`customer_id`, `document_type`) to live alongside unstructured JSON documents (`metadata`).
* **High-Performance Querying:** Utilizes Oracle SQL operators (`JSON_VALUE`, `JSON_QUERY`) and native search indexing to query nested JSON paths with blazing-fast execution speeds.

---

## 3. Database Schema Script (`06_nosql_json_models.sql`)
The complete, production-ready script creates the table, inserts structured JSON financial documents, executes path-extraction queries, and builds the native search index:

```sql
--------------------------------------------------------------------------------
-- Portfolio 4: NoSQL, JSON, and Advanced Data Models
-- Organisation: Ibukun Investment Management Company
-- Database: Oracle Database (Native JSON Data Type Implementation)
--------------------------------------------------------------------------------

SET DEFINE OFF;
SET SERVEROUTPUT ON;

PROMPT 
PROMPT ==============================================================================
PROMPT 1. Creating Semi-Structured JSON Storage Table for Market Feeds & Client Portfolios
PROMPT ==============================================================================

-- Create table using Oracle native JSON data type with conditional exception handling
BEGIN
    EXECUTE IMMEDIATE '
    CREATE TABLE client_portfolio_payloads (
        payload_id      NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        customer_id     NUMBER NOT NULL,
        document_type   VARCHAR2(50) NOT NULL,
        metadata        JSON,
        created_at      TIMESTAMP DEFAULT SYSTIMESTAMP
    )';
    DBMS_OUTPUT.PUT_LINE('Table client_portfolio_payloads created successfully.');
EXCEPTION
    WHEN OTHERS THEN
        IF SQLCODE = -00955 THEN
            DBMS_OUTPUT.PUT_LINE('Table client_portfolio_payloads already exists. Proceeding with existing table.');
        ELSE
            RAISE;
        END IF;
END;
/

PROMPT 
PROMPT ==============================================================================
PROMPT 2. Inserting Flexible JSON Document Payloads
PROMPT ==============================================================================

-- Insert a sample flexible investment profile document into the JSON column
INSERT INTO client_portfolio_payloads (customer_id, document_type, metadata)
VALUES (
    1, 
    'INVESTMENT_PREFERENCES', 
    '{"risk_profile": "MODERATE", "asset_allocation": {"equity": 60, "fixed_income": 30, "cash": 10}, "notification_channels": ["EMAIL", "SMS"], "auto_rebalance": true}'
);

-- Insert a real-time market data feed document payload
INSERT INTO client_portfolio_payloads (customer_id, document_type, metadata)
VALUES (
    1, 
    'MARKET_FEED_SNAPSHOT', 
    '{"ticker": "IIMC_BLUECHIP", "current_price": 1050.25, "daily_change_pct": 2.45, "exchange": "NGX", "volume": 450000}'
);

COMMIT;
PROMPT Sample JSON document payloads inserted successfully.

PROMPT 
PROMPT ==============================================================================
PROMPT 3. Querying Semi-Structured JSON Data Using SQL Operators (JSON_VALUE)
PROMPT ==============================================================================

DECLARE
    v_risk_level VARCHAR2(50);
    v_ticker     VARCHAR2(50);
    v_price      NUMBER;
BEGIN
    -- Extract specific fields from the JSON document using JSON_VALUE
    SELECT JSON_VALUE(metadata, '$.risk_profile')
    INTO v_risk_level
    FROM client_portfolio_payloads
    WHERE customer_id = 1 AND document_type = 'INVESTMENT_PREFERENCES';

    DBMS_OUTPUT.PUT_LINE('Extracted Customer Risk Profile (JSON): ' || v_risk_level);

    -- Extract market feed details
    SELECT JSON_VALUE(metadata, '$.ticker'), JSON_VALUE(metadata, '$.current_price' RETURNING NUMBER)
    INTO v_ticker, v_price
    FROM client_portfolio_payloads
    WHERE document_type = 'MARKET_FEED_SNAPSHOT';

    DBMS_OUTPUT.PUT_LINE('Extracted Market Feed - Ticker: ' || v_ticker || ' | Price: NGN ' || v_price);
END;
/

PROMPT 
PROMPT ==============================================================================
PROMPT 4. Creating a Native JSON Search Index for High-Performance NoSQL Querying
PROMPT ==============================================================================

-- Create a native search index on the metadata column for fast JSON path querying
BEGIN
    EXECUTE IMMEDIATE 'CREATE SEARCH INDEX idx_json_metadata ON client_portfolio_payloads (metadata)';
    DBMS_OUTPUT.PUT_LINE('Native JSON Search Index created successfully.');
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('Note: Index creation message: ' || SQLERRM);
END;
/

PROMPT 
PROMPT ==============================================================================
PROMPT Portfolio 4 NoSQL & Advanced Data Models Script Completed Successfully.
PROMPT ==============================================================================
```
